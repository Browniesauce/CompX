# Architecture

CompX is a local-first Python command-line application. Typer defines `compx` commands in `src/compx/cli.py`: `--help`, `init`, `import` (with `--dry-run`), `sync` (preview or `--apply`), `history`, `search`, `show`, `compare`, and `export`. The CLI parses arguments and reports results; parsing, query behavior, SQL, comparison logic, serialization, and output formatting live in separate modules.

`src/compx/csv_import.py` reads the entire CSV, checks headers and row values, detects repeated manufacturer/SKU identities, and asks the repository for identities already in the catalog. It produces validated records and issues without writing to SQLite. `src/compx/models.py` holds the validated record type.

`src/compx/repository.py` reads catalog identities and writes validated records with parameterized SQL. Real import first validates the whole file. The repository then creates or upgrades the schema if needed, starts an immediate SQLite transaction, checks identities again against concurrent imports, and inserts all manufacturers, families, configurations, and sources. A failed write rolls back all rows from the import. A dry run opens an existing database read-only and does not create an absent database.

`src/compx/database.py` chooses the default data path, opens SQLite connections with foreign-key enforcement, and applies `schema.sql`. `init` is repeatable and preserves rows. Phase 2 includes a specific upgrade from the Phase 1 schema; it does not introduce a general migration framework. Tests use temporary directories and synthetic records, never the user's default catalog.

`src/compx/catalog.py` validates and combines search filters and detail IDs. The repository builds parameterized SQLite queries, reads the existing catalog without creating or upgrading it, and returns typed result objects. `src/compx/formatting.py` renders a plain-text search table and device detail view, including unknown values and sources. Search uses the persistent `configurations.id` primary key for both result rows and `show`. No Phase 3 schema change is needed. A legacy Phase 1 database needs the existing `compx init` upgrade before these read commands can use it.

`src/compx/comparison.py` loads two IDs through the detail service and classifies each known, unknown, or category-specific field. `src/compx/formatting.py` renders the comparison table and source sections. `src/compx/exporting.py` selects IDs using the same `search_catalog` filters and ordering, loads all associated source records, and serializes CSV or JSON with standard-library modules. It writes to standard output through the CLI or to an output file with exclusive creation by default. Explicit overwrite uses a temporary file and atomic replacement. Compare and export only read the catalog. Phase 4 needs no schema migration or new dependency.

The Phase 5 integration test runs the full CLI workflow against a temporary SQLite file and clearly synthetic demo CSV. `pyproject.toml` defines the installable `compx` entry point, while `schema.sql` is packaged as a resource. `MANIFEST.in` includes documentation and demo CSV files in the source distribution. The runtime remains local and makes no network requests.

Phase 7 adds `compx source parse`. `src/compx/source_pdf.py` extracts embedded text from a local PDF with pypdf. `src/compx/psref_adapter.py` recognizes the SKU-specific Lenovo PSREF ThinkPad model-detail layout and official URL shape. Phase 8 adds the separate `src/compx/psref_desktop.py` parser and mapper for ThinkCentre M70s Gen 5 model-detail PDFs. `src/compx/source_review.py` selects the laptop or desktop mapping, formats the human review, checks the existing CSV contract, and writes a candidate only on explicit `--output`. The source adapter never opens SQLite or fetches URLs. The existing `sync` command remains the separate catalog update step. See [source documentation](sources.md) for labels and limits.

`src/compx/sync.py` reuses CSV validation, reads manufacturer/SKU identities and complete snapshots, and classifies rows without writing. `--apply` rechecks the plan under an immediate SQLite write lock and calls repository SQL helpers to insert or update all rows in one transaction. The repository preserves older source records and writes a revision for each addition or update. `src/compx/revision_data.py` owns snapshot serialization and revision writes; `src/compx/history.py` reads and formats revisions in recorded order. `src/compx/database.py` creates a forward-only history table and baselines older configurations once. Preview and history reads do not initialize or modify a database.
